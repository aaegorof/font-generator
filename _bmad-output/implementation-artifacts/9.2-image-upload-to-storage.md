# Story 9.2: Image Upload to Storage

## Description

Мигрировать загрузку изображений с локального Express сервера на Supabase Storage. Реализовать загрузку файлов изображений в bucket `user-images`, генерацию публичных URL и отображение изображений из Storage в тайлах.

## User Story

**As a** авторизованный пользователь  
**I want** загружать изображения в облачное хранилище  
**So that** они были доступны с любого устройства

## Goals

- Загружать файлы изображений в Supabase Storage bucket `user-images`
- Генерировать публичные URL для загруженных изображений
- Отображать изображения из Storage в тайлах
- Обновить метаданные изображения в таблице `user_images`
- Сохранить обратную совместимость с существующим UI

## Acceptance Criteria

### Image Upload Service

Обновить `src/services/imageSync.ts`:

```typescript
import { supabase } from '../lib/supabase'

export class ImageSyncService {
  // ... existing methods ...

  /**
   * Upload image file to Supabase Storage
   */
  static async uploadImage(
    userId: string,
    file: File,
  ): Promise<{ url: string; storagePath: string }> {
    try {
      // Validate file
      this.validateImageFile(file)

      // Generate storage path
      const imageId = `img-${Date.now()}-${Math.random().toString(36).substr(2, 9)}`
      const fileExt = file.name.split('.').pop()
      const storagePath = `${userId}/${imageId}.${fileExt}`

      // Upload to Storage
      const { data, error } = await supabase.storage.from('user-images').upload(storagePath, file, {
        cacheControl: '3600',
        upsert: false,
      })

      if (error) throw error

      // Get public URL
      const { data: urlData } = supabase.storage.from('user-images').getPublicUrl(storagePath)

      return {
        url: urlData.publicUrl,
        storagePath: storagePath,
      }
    } catch (err) {
      console.error('Error uploading image:', err)
      throw err
    }
  }

  /**
   * Delete image file from Storage
   */
  static async deleteImageFile(storagePath: string): Promise<void> {
    try {
      const { error } = await supabase.storage.from('user-images').remove([storagePath])

      if (error) throw error
    } catch (err) {
      console.error('Error deleting image file:', err)
      throw err
    }
  }

  /**
   * Validate image file
   */
  private static validateImageFile(file: File): void {
    // Check file size (max 10 MB)
    const maxSize = 10 * 1024 * 1024
    if (file.size > maxSize) {
      throw new Error('Image file too large (max 10 MB)')
    }

    // Check file type
    const allowedTypes = ['image/jpeg', 'image/jpg', 'image/png', 'image/webp']

    if (!allowedTypes.includes(file.type)) {
      throw new Error('Invalid image file type (allowed: .jpg, .jpeg, .png, .webp)')
    }
  }

  /**
   * Save image with file
   */
  static async saveImageWithFile(userId: string, file: File): Promise<string> {
    try {
      // Upload file to Storage
      const { url, storagePath } = await this.uploadImage(userId, file)

      // Save to database
      const { error } = await supabase.from('user_images').insert({
        user_id: userId,
        url: url,
        storage_path: storagePath,
      })

      if (error) throw error

      return url
    } catch (err) {
      console.error('Error saving image with file:', err)
      throw err
    }
  }

  /**
   * Delete image with file
   */
  static async deleteImageWithFile(userId: string, url: string): Promise<void> {
    try {
      // Get storage path from database
      const { data, error: fetchError } = await supabase
        .from('user_images')
        .select('storage_path')
        .eq('user_id', userId)
        .eq('url', url)
        .single()

      if (fetchError) throw fetchError

      // Delete from database
      await this.deleteImage(userId, url)

      // Delete file from Storage if exists
      if (data?.storage_path) {
        await this.deleteImageFile(data.storage_path)
      }
    } catch (err) {
      console.error('Error deleting image with file:', err)
      throw err
    }
  }
}
```

```typescript
import { ImageSyncService } from '../services/imageSync'
import { getCurrentUserId } from '../utils/auth'

const handleFileUpload = async (file: File) => {
  try {
    setUploading(true)
    setError(null)

    const userId = await getCurrentUserId()
    if (!userId) {
      throw new Error('User not authenticated')
    }

    // Upload image with file
    const url = await ImageSyncService.saveImageWithFile(userId, file)

    // Add to store (will trigger sync)
    addImage(url)

    setUploading(false)
  } catch (err) {
    console.error('Error uploading image:', err)
    setError(err instanceof Error ? err.message : 'Upload failed')
    setUploading(false)
  }
}

const handleDeleteImage = async (url: string) => {
  try {
    const userId = await getCurrentUserId()
    if (!userId) {
      // Fallback to local delete
      removeImage(url)
      return
    }

    // Delete image with file
    await ImageSyncService.deleteImageWithFile(userId, url)

    // Remove from store
    removeImage(url)
  } catch (err) {
    console.error('Error deleting image:', err)
    setError(err instanceof Error ? err.message : 'Delete failed')
  }
}
```

## Edge Cases

### Case 1: Duplicate Filename

- Если файл с таким именем уже существует
- Использовать `upsert: false` чтобы предотвратить перезапись
- Генерировать уникальный ID для каждого изображения

### Case 2: Upload Failure

- Если загрузка не удалась (сеть, права доступа)
- Показать ошибку
- Не создавать запись в `user_images`
- Retry опция для пользователя

### Case 3: Orphaned Files

- Если запись в БД удалена, но файл остался в Storage
- Реализовать cleanup job (future)
- Или использовать RLS policies для автоматического удаления

### Case 4: Missing Storage Path

- Если в БД нет `storage_path` для изображения
- Предположить что это внешний URL
- Не пытаться удалить из Storage

### Case 5: Large Images

- Если изображение очень большое (высокое разрешение)
- Показать warning о размере файла
- Рекомендовать оптимизацию (future: auto-resize)

## Performance Considerations

### Optimization Strategies

1. **Image Compression**: Использовать WebP формат (лучшее сжатие)
2. **Caching**: Использовать `cacheControl: '3600'` для кэширования
3. **Lazy Loading**: Загружать изображения по требованию
4. **Thumbnails**: Генерировать thumbnails для списка (future)
5. **Progressive Loading**: Показывать placeholder во время загрузки

### Storage Limits

- Max file size: 10 MB (настраивается)
- Bucket size: Unlimited (зависит от Supabase плана)
- RLS policies: Защищают от несанкционированного доступа
