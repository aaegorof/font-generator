# Story 9.3: File Deletion from Storage

## Description

Обеспечить корректное удаление файлов (шрифтов и изображений) из Supabase Storage при удалении через UI. Реализовать каскадное удаление: при удалении записи из БД также удаляется файл из Storage.

## User Story

**As a** авторизованный пользователь  
**I want** чтобы при удалении шрифта или изображения файл также удалялся из облака  
**So that** я не тратил место в хранилище на неиспользуемые файлы

## Goals

- Обеспечить каскадное удаление файлов при удалении из UI
- Удалять файлы шрифтов из `user-fonts` bucket
- Удалять файлы изображений из `user-images` bucket
- Обработать ошибки удаления
- Предотвратить orphaned files (файлы без записей в БД)

## Acceptance Criteria

### Must Have

- [ ] При удалении шрифта — файл удаляется из Storage
- [ ] При удалении изображения — файл удаляется из Storage
- [ ] При удалении записи из БД — файл удаляется из Storage
- [ ] Ошибки удаления обрабатываются корректно
- [ ] UI показывает статус удаления

### Should Have

- [ ] Confirmation dialog перед удалением
- [ ] Batch deletion для множественных файлов
- [ ] Cleanup orphaned files (future)

## Technical Details

### Deletion Flow

```
User clicks "Delete" → Confirmation → Delete from DB → Delete from Storage → Update UI
```

### Enhanced Deletion Methods

Методы уже реализованы в Stories 9.1 и 9.2, но нужно обеспечить их корректную интеграцию:

#### Font Deletion (from `fontSync.ts`)

```typescript
static async deleteFontWithFile(userId: string, fontId: string): Promise<void> {
  try {
    // Get storage path from database
    const { data, error: fetchError } = await supabase
      .from('user_fonts')
      .select('storage_path')
      .eq('user_id', userId)
      .eq('font_def->id', fontId)
      .single()

    if (fetchError) throw fetchError

    // Delete from database first
    await this.deleteFont(userId, fontId)

    // Delete file from Storage if exists
    if (data?.storage_path) {
      await this.deleteFontFile(data.storage_path)
    }
  } catch (err) {
    console.error('Error deleting font with file:', err)
    throw err
  }
}
```

```typescript
const handleDeleteFont = async (fontId: string) => {
  try {
    // Show confirmation
    const confirmed = window.confirm('Are you sure you want to delete this font?')
    if (!confirmed) return

    setDeleting(fontId)
    setError(null)

    const userId = await getCurrentUserId()
    if (!userId) {
      // Fallback to local delete
      removeFont(fontId)
      return
    }

    // Delete font with file
    await FontSyncService.deleteFontWithFile(userId, fontId)

    // Remove from store
    removeFont(fontId)

    // Remove @font-face
    removeUploadedFont(fontId)

    setDeleting(null)
  } catch (err) {
    console.error('Error deleting font:', err)
    setError(err instanceof Error ? err.message : 'Delete failed')
    setDeleting(null)
  }
}
```

### Batch Deletion

Создать `src/services/batchDelete.ts`:

```typescript
import { FontSyncService } from './fontSync'
import { ImageSyncService } from './imageSync'

export class BatchDeleteService {
  /**
   * Delete multiple fonts
   */
  static async deleteFonts(userId: string, fontIds: string[]): Promise<void> {
    const results = await Promise.allSettled(
      fontIds.map((id) => FontSyncService.deleteFontWithFile(userId, id)),
    )

    const errors = results
      .filter((r) => r.status === 'rejected')
      .map((r) => (r as PromiseRejectedResult).reason)

    if (errors.length > 0) {
      console.error('Batch delete errors:', errors)
      throw new Error(`Failed to delete ${errors.length} fonts`)
    }
  }

  /**
   * Delete multiple images
   */
  static async deleteImages(userId: string, urls: string[]): Promise<void> {
    const results = await Promise.allSettled(
      urls.map((url) => ImageSyncService.deleteImageWithFile(userId, url)),
    )

    const errors = results
      .filter((r) => r.status === 'rejected')
      .map((r) => (r as PromiseRejectedResult).reason)

    if (errors.length > 0) {
      console.error('Batch delete errors:', errors)
      throw new Error(`Failed to delete ${errors.length} images`)
    }
  }
}
```

## Edge Cases

### Case 1: File Not Found in Storage

- Если файл уже удален из Storage
- Игнорировать ошибку 404
- Удалить запись из БД

### Case 2: Database Delete Fails

- Если не удалось удалить запись из БД
- Не удалять файл из Storage
- Показать ошибку пользователю

### Case 3: Storage Delete Fails

- Если не удалось удалить файл из Storage
- Запись уже удалена из БД
- Файл станет orphaned
- Логировать для cleanup job (future)

### Case 4: Concurrent Deletion

- Если пользователь удаляет файл одновременно с разных устройств
- Первое удаление успешно
- Второе получит 404 (файл не найден)
- Обработать gracefully

### Case 5: Deletion During Upload

- Если пользователь удаляет файл во время загрузки
- Отменить загрузку
- Удалить частично загруженный файл

## Performance Considerations

### Optimization Strategies

1. **Batch Deletion**: Удалять множество файлов одним запросом
2. **Background Jobs**: Для cleanup orphaned files (future)
3. **Soft Delete**: Помечать как удаленные, удалять позже (future)
4. **Retry Logic**: Повторять неудачные удаления

## Notes

- Удаление из БД происходит первым для предотвращения orphaned records
- Если удаление из Storage не удалось, файл станет orphaned
- Orphaned files можно очистить background job (future)
- RLS policies автоматически защищают от несанкционированного удаления
- Default файлы (Google Fonts, DEFAULT_IMAGES) не имеют storage_path и не удаляются из Storage
