# Story 7.3: Build Auth UI - Login/Logout Buttons

## Description

Создать UI компоненты для авторизации пользователей через Google OAuth. Реализовать кнопки "Sign in with Google" и "Sign out", отображение информации о пользователе, и интеграцию с уже настроенной Google OAuth инфраструктурой из Story 6.2.

## User Story

**As a** пользователь  
**I want** видеть кнопку входа через Google и возможность выйти из аккаунта  
**So that** я могу авторизоваться и управлять своей сессией

## Goals

- Создать компонент кнопки "Sign in with Google"
- Создать компонент кнопки "Sign out"
- Отобразить email авторизованного пользователя
- Интегрировать с Google OAuth flow из Story 6.2
- Обеспечить корректную работу авторизации согласно документации

## Technical Context

### Completed Infrastructure (Story 6.2)

Согласно `_bmad-output/implementation-artifacts/6.2-google-oauth-config.md`:

**Google OAuth Configuration:**

- Supabase Auth настроен с Google OAuth provider
- Config в `supabase/config.toml`:
  ```toml
  [auth.external.google]
  enabled = true
  client_id = "env(SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID)"
  secret = "env(SUPABASE_AUTH_EXTERNAL_GOOGLE_SECRET)"
  skip_nonce_check = true
  ```

**Redirect URLs:**

- Site URL: `http://localhost:5173`
- Redirect URLs:
  - `http://localhost:5173`
  - `http://localhost:5173/auth/callback`
  - `http://127.0.0.1:5173`

**Auth Endpoint:**

- Authorization URL: `http://127.0.0.1:54321/auth/v1/authorize?provider=google&redirect_to=http://localhost:5173`

**Environment Variables (from .env):**

```bash
SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID=<your-client-id>
SUPABASE_AUTH_EXTERNAL_GOOGLE_SECRET=<your-secret>
VITE_GOOGLE_CLIENT_ID=<your-client-id>
VITE_SUPABASE_URL=http://127.0.0.1:54321
VITE_SUPABASE_ANON_KEY=<anon-key>
```

### Component: AuthButton.tsx

**Location:** `src/components/Auth/AuthButton.tsx`

**Purpose:** Main authentication button that shows different states based on auth status

**Requirements:**

1. Show "Sign in with Google" button when user is not authenticated
2. Show user email and "Sign out" button when authenticated
3. Handle loading states during authentication
4. Use `useAuth` hook for auth state management
5. Follow existing UI patterns from the project

**Expected Behavior:**

```typescript
// Unauthenticated state:
<button onClick={signInWithGoogle}>
  <GoogleIcon /> Sign in with Google
</button>

// Authenticated state:
<div>
  <span>{user.email}</span>

</div>

// Loading state:
<div>Loading...</div>
```

**Integration with Google OAuth:**

- Call `supabase.auth.signInWithOAuth({ provider: 'google' })` from useAuth hook
- Supabase will redirect to: `http://127.0.0.1:54321/auth/v1/authorize?provider=google`
- After Google authorization, redirect back to: `http://localhost:5173/auth/callback`
- Handle callback in AuthCallback component or route

## Dev Notes

### Key Integration Points

1. **Supabase Client** (from Story 7.1):

   ```typescript
   import { supabase } from '@/lib/supabase'
   ```

2. **Auth Hook** (from Story 7.2):

   ```typescript
   import { useAuth } from '@/hooks/useAuth'
   const { user, loading, signInWithGoogle, signOut } = useAuth()
   ```

3. **OAuth Endpoint** (from Story 6.2):
   - Base URL: `http://127.0.0.1:54321`
   - Auth path: `/auth/v1/authorize?provider=google`
   - Redirect: `http://localhost:5173/auth/callback`

### Implementation Order

1. Create AuthButton component (basic structure)
2. Integrate useAuth hook
3. Implement sign in flow
4. Implement sign out flow
5. Add loading states

### Common Pitfalls to Avoid

1. **Don't hardcode URLs** - Use environment variables
2. **Don't forget loading states** - User needs feedback
3. **Don't skip error handling** - OAuth can fail
4. **Don't forget redirect_to parameter** - User should return to where they were
5. **Don't expose tokens** - Keep them secure
6. **Don't skip accessibility** - Make it usable for everyone

### Success Indicators

- User can sign in with one click
- No console errors during auth flow
- UI updates immediately after auth state change
- Works on mobile and desktop
- Accessible via keyboard
- Error messages are helpful
